# Работа с проектом «Фитнес-агент»

Учебный проект: Streamlit-приложение, в котором пользователь заполняет анкету,
а Gemini проверяет её на безопасность, составляет программу тренировок
и план питания. Автор — новичок в программировании, поэтому код простой
и прямолинейный: обычные функции, никаких классов и абстракций.

Главные правила проекта лежат в `CLAUDE.md` — они обязательны.
Этот скилл не повторяет их, а показывает **порядок действий** для частых задач.

## Шаг 0: с чего начинать любую задачу

1. Прочитай `CLAUDE.md` — там архитектурные договорённости и запреты.
2. Найди по таблице ниже, какой файл трогать. Не ищи по всему проекту:
   файлов мало, у каждого одна роль.
3. Делай **одно изменение за раз**. Не рефакторить код «попутно»,
   даже если видишь, как сделать красивее.
4. Все комментарии и тексты в интерфейсе — **на русском**.

## Карта файлов: куда смотреть

| Задача | Файл |
|---|---|
| Интерфейс, анкета, вывод плана, CSS | `app.py` |
| Вызов модели, обработка ошибок API, константа `MODEL` | `agent/llm.py` |
| Порядок шагов, чтение промптов, демо-режим | `agent/pipeline.py` |
| Текст инструкций модели | `agent/prompts/safety.md`, `workout.md`, `nutrition.md` |
| Цвета темы, порт, headless | `.streamlit/config.toml` |
| Анкета-пример (кнопка «Заполнить пример») | `examples/sample_profile.json` |
| Сохранённые ответы для демо-режима | `examples/demo_responses/` |
| Разовый прогон для записи демо-ответов | `scripts/zapisat_demo.py` |
| Описание проекта для читателя | `README.md` |

Жёсткие границы, которые нельзя нарушать:

- `google.genai` импортируется **только** в `agent/llm.py`. Название модели —
  только там же, в константе `MODEL`.
- Промпты — **только файлами** в `agent/prompts/`, никогда строками в коде.
- API-ключ не попадает ни в код, ни в файлы, ни в `.env`, ни в логи,
  ни в вывод `print`. Пользователь вводит его в боковой панели.
- Новые файлы, модули, конфиги, тесты и утилиты — **сначала спросить**.

## Запуск приложения

```powershell
cd C:\Users\Lenovo\projects\fitness-agent
venv\Scripts\Activate.ps1
streamlit run app.py
```

Адрес: `http://localhost:8501`. В `config.toml` стоит `headless = true`,
поэтому браузер сам не откроется — открывай ссылку вручную.

Запускай сервер в фоне (`run_in_background`), иначе он заблокирует сессию.

**Важно про перезапуск.** Streamlit подхватывает правки только в `app.py`.
Файлы из `agent/` он держит в памяти такими, какими импортировал при старте.
После правок в `agent/*.py` сервер нужно **остановить и запустить заново** —
иначе страница падает на старом коде, например с `ImportError`
на только что добавленной функции.

Проверять изменения вёрстки — в браузере. Streamlit часто ужимает блоки
по содержимому, селекторы вида `[data-testid="..."]` подсматривай в разметке
живой страницы, а не угадывай.

## Рецепты частых изменений

### Добавить или изменить поле анкеты

Поле живёт в трёх местах, пропустить нельзя ни одно:

1. `POLYA` в `app.py` — `ключ виджета: "Подпись, под которой ответ уходит модели"`.
2. Сам виджет в блоке `with st.form("anketa")` — с тем же `key=`.
3. `examples/sample_profile.json` — значение под той же подписью,
   иначе кнопка «Заполнить пример» упадёт с `KeyError`.

Если поле необязательное и текстовое, пустое значение превращается
в `"не указаны"` — это уже делает общий цикл сборки `otvety`.

Подумай, нужно ли упомянуть новое поле в промптах `agent/prompts/*.md`:
модель получает анкету одним текстом, но может не знать, что делать
с незнакомой строкой.

### Поправить промпт

Меняй только файл в `agent/prompts/`. Код трогать не нужно.

Если промпт поменялся заметно — сохранённые демо-ответы устарели.
Перезапиши их (см. ниже) или честно скажи пользователю, что они расходятся.

### Сменить модель

Одна строка — `MODEL` в начале `agent/llm.py`. Больше нигде.
Повтор при ошибке 5xx (3 попытки с паузой 5 секунд) **не убирать** —
это нормальное поведение бесплатного тарифа.

### Поменять оформление

Цвета темы — `.streamlit/config.toml`. Всё остальное — один блок CSS
в переменной `STILI` в начале `app.py`. Новых css-файлов не заводить.

### Перезаписать демо-ответы

Файлы в `examples/demo_responses/` — **настоящие** ответы модели.
Руками их не сочинять никогда.

```powershell
venv\Scripts\Activate.ps1
python scripts/zapisat_demo.py
```

Скрипт спросит ключ скрытым вводом (или возьмёт `GEMINI_API_KEY`
из переменных окружения) и прогонит все три шага на `sample_profile.json`.
Ключ в файлы проекта не попадает.

Запускать скрипт сам не пытайся без ключа — он требует ввода
и в неинтерактивной сессии зависнет. Попроси пользователя выполнить
команду через `! python scripts/zapisat_demo.py`.

### Работа с выводом и состоянием

Streamlit перезапускает скрипт при любом действии на странице, включая
изменение размера окна. Поэтому ответы анкеты, план и текст ошибки лежат
в `st.session_state` (`otvety`, `plan`, `oshibka`, `demo`), а блок вывода
читает их оттуда.

Две ловушки, на которые уже наступали:

- Ключ `anketa` в `session_state` занят формой `st.form("anketa")`
  и доступен только для чтения. Свои данные туда класть нельзя —
  поэтому ответы лежат под ключом `otvety`.
- Значение виджета разрешено менять только **до** его создания. Поэтому
  «Заполнить пример» поднимает флаг `zapolnit_primer` и вызывает `st.rerun()`,
  а подстановка идёт в блоке перед формой.

## Разбор ошибок

Сначала смотри на текст в интерфейсе: ошибки API уже переведены
на понятный язык в `agent/llm.py` через `OshibkaAPI` (что случилось + совет).
Новую ошибку API добавляй туда же, а не в `app.py`.

| Симптом | Причина | Что делать |
|---|---|---|
| `ImportError` на только что добавленной функции | Streamlit держит старый `agent/*.py` в памяти | Перезапустить сервер |
| `KeyError` с подписью поля | Поле есть в `POLYA`, но нет в `sample_profile.json` | Дописать значение в пример |
| «Ключ не подошёл» | 401/403 от Google | Проверить ключ, пробелы по краям |
| «Бесплатных запросов на сегодня больше нет» | 429, лимит тарифа | Подождать минуту или убрать ключ и смотреть демо |
| «Модель сейчас перегружена» | 5xx после 3 попыток | Обычное дело на бесплатном тарифе, попробовать позже |
| «Модель ответила не тем, что мы ждали» | Шаг 1 вернул не JSON | Повторить; схема `SHEMA_BEZOPASNOSTI` обычно это предотвращает |
| «Сохранённого примера плана нет» | Нет файлов в `examples/demo_responses/` | Прогнать `scripts/zapisat_demo.py` |
| Ответ оборвался на полуслове | Упёрлись в `max_output_tokens` | Поднять лимит в вызове из `pipeline.py` |

Правила показа ошибок: жёлтый `st.warning` двумя частями (что случилось
и что делать). Красный `st.error` оставлен только для статуса `stop` —
там это по делу.

Отдельно проверяй **честность демо-режима**: приложение обязано писать,
что показывает заранее записанный пример для анкеты из `sample_profile.json`,
а не ответ модели на введённые данные. Выдуманный план вместо настоящего —
не показывать никогда.

## Обновление README

`README.md` написан для человека, который видит проект впервые:
без жаргона, с готовыми командами для Windows и macOS.
Держи этот тон.

Разделы по порядку: «Зачем это нужно» → «Как работает» → «Как выглядит» →
«Установка» → «Запуск» → «Ключ Gemini и демо-режим» → «Пример сценария» →
«Технологии» → «Структура проекта» → «Ограничения» → «Развитие проекта» →
«Об авторстве кода».

Что синхронизировать при изменениях в коде:

- Поменялась структура файлов → раздел «Структура проекта».
- Поменялись шаги пайплайна → раздел «Как работает».
- Поменялась модель или библиотека → «Технологии» и `requirements.txt`.
- Поменялась анкета или вёрстка → скриншоты в `screenshots/`
  (`anketa.png`, `plan.png`, `pitanie.png`) и раздел «Как выглядит».
- Появилось ограничение, о котором стоит знать → «Ограничения».

Скриншоты не выдумывай и не рисуй: это снимки живого приложения.
Если они устарели — запусти приложение и попроси пользователя
пересохранить их, либо сделай снимки через браузерную автоматизацию.

## Подготовка к публикации

Пройди список целиком и отчитайся по каждому пункту.

1. **Секретов нет.** `.env` в `.gitignore` и не в индексе; ключа нет
   ни в одном файле проекта, ни в истории коммитов, ни в скриншотах
   (поле ключа — `type="password"`, но проверь боковую панель на снимках).
2. **Мусора нет.** В индексе нет `venv/`, `__pycache__/`, `*.pyc`.
3. **Установка работает с нуля.** `requirements.txt` содержит всё, что
   импортируется: `streamlit`, `google-genai`, `python-dotenv`.
   Команды из README выполняются в чистой папке без ошибок.
4. **Демо-режим работает без ключа.** Запусти приложение, не вводи ключ,
   нажми «Заполнить пример» → «Составить план». План должен появиться
   вместе с честной плашкой про демо-режим.
5. **Демо-ответы не расходятся с промптами.** Если промпты правились
   после последнего прогона — перезаписать.
6. **Скриншоты соответствуют текущему интерфейсу.**
7. **README актуален** по списку выше.
8. **`DEMO_MODE` в `.env.example` стоит `false`** — образец настроек
   описывает обычную работу.

Коммитить и пушить — **только по явной просьбе**. Сам инициативу не проявляй.
